# 03 · 证据与溯源

> 本文件定义"什么算证据、怎么入库、怎么支撑结论"。它是整套框架可信度的支点，也是 `sa lint` 的校验依据。

## 1. 证据分级

| 级别 | 定义 | 例 |
|---|---|---|
| **E1** | 一手原始数据 / 原始披露 | 国家统计局、SEC 申报、企业公告原文、Wind/交易所行情、原始论文数据、访谈逐字稿 |
| **E2** | 权威二手，且有方法与口径披露 | 政府/国际组织报告、同行评议综述、券商深度（署名+日期）、行业协会统计 |
| **E3** | 一般二手 | 主流媒体报道、无方法披露的白皮书、咨询公司宣传材料 |
| **E4** | 观点与线索 | 自媒体、论坛、百科、AI 摘要、匿名信源 |

**使用规则：**

- 核心结论（进摘要/选项依据的）**至少一个 E1 或两个独立 E2**。
- E4 只能当线索：必须沿它回溯到 E1–E3 并单独入库，**不得直接作为 claim 的证据**。
- "独立"指不同发布方、不同原始数据源；同一篇稿件的转载不算两个来源。

**化学结构**：以 PubChem 的 CID/SMILES/分子式/分子量为 E1 记录；结构图由 RDKit 从 SMILES 绘制，报告必须保留 CID 与 SMILES 以便复核。骨架高亮须注明 SMARTS 或匹配方法；未匹配处要显式说明，不得用示意图冒充结构证据。

## 2. 来源信封

每个来源一个目录 `search/s-XXXX-<slug>/`，必含 `meta.json`：

```json
{
  "id": "s-0001",
  "title": "2025 年中国集成电路产业运行情况",
  "source_type": "gov | database | filing | paper | web | interview | internal",
  "tool": "datasource:china_nbs | websearch | browser | manual",
  "query": { "text": "集成电路 产量 2025", "params": {} },
  "locator": "https://... 或数据集标识/文件路径",
  "publisher": "国家统计局",
  "published_at": "2026-01-20",
  "retrieved_at": "2026-10-20T10:32:00+08:00",
  "period": { "start": "2025-01-01", "end": "2025-12-31" },
  "evidence_grade": "E1",
  "license": "公开",
  "raw": [{ "path": "raw/ic_output.csv", "sha256": "...", "bytes": 10240 }],
  "notes": "月度数据，已按年汇总"
}
```

**必填**：`id / title / source_type / tool / locator / publisher / retrieved_at / evidence_grade`。缺一即 lint 报错。

**`extracted.md` 的写法**（人读入口，也是复核入口）：

```markdown
# s-0001 · 2025 年中国集成电路产业运行情况

- 定位符：表 3-2，第 2 页
- 取数时间：2026-10-20 10:32
- 口径：规模以上企业，累计值，同比按可比口径

## 关键摘录
> 2025 年集成电路产量 4,514 亿块，同比增长 12.3%。

## 加工说明
- 原始 CSV 的"同比增长"列为累计同比，未做年化。
```

**纪律：** `extracted.md` 里不得出现原文没有的判断；自己的推断写到 `analysis/notes/`。

关键论文的摘录保留实际阅读范围、方法/对照、结果与图表定位；分析按[13](13-研究分析与论证.md)说明这些观察怎样支持具体结论。E1只表示来源性质，不能代替实际阅读程度、因果强度或跨研究综合。

## 3. 结论台账 `claims.json`

```json
{
  "claims": [
    {
      "id": "c-0001",
      "statement": "2025 年中国集成电路产量同比增长约 12%，高于全球平均增速。",
      "confidence": "high",
      "evidence": ["s-0001", "s-0009"],
      "counter_evidence": ["s-0014"],
      "conflicts": [],
      "scope": "中国大陆，规模以上企业，2025 全年",
      "as_of": "2026-10-20",
      "status": "active",
      "supersedes": null,
      "first_asserted": "2026-10-20",
      "last_reviewed": "2026-10-22",
      "owner": "worker-1"
    }
  ]
}
```

字段纪律：

- `statement` 必须是**可判真假的单句**，不含"可能/据了解"。模糊判断拆成多条或降级为假设。
- `status`：`draft → active → superseded / retracted`。推翻不删记录，标 `superseded` 并指向新 claim。
- `scope` 写清地域、主体、期间、口径——这是后续复用时不误用的关键。
- `counter_evidence` 即使为空也要显式写 `[]`；空表示"查过没有"，不是"没查"。

## 4. 置信度判定

| 置信度 | 条件（同时满足） |
|---|---|
| **high** | ≥2 个相互独立的 E1/E2 来源，口径一致；反证轮无实质冲突；数字可复算 |
| **medium** | 1 个 E1/E2，或 ≥2 个独立 E3 一致；无未解释冲突 |
| **low** | 仅 E3/E4；口径不明；存在未决冲突；推算值且假设敏感 |

**降级触发**：来源过期（见 §7）、冲突未解释、复算不一致、依赖未验证的假设。
**不得自定义档位**（如"较高""基本确定"）；报告里的措辞由置信度映射（见 `05-报告规范.md`）。

## 5. 基准事实 `facts.json`（调研版 golden）

关键数字一旦要反复引用，就从 claim 提升为 fact，冻结为断言：

```json
{
  "facts": [
    {
      "id": "f-0001",
      "metric": "中国集成电路产量",
      "value": 4514,
      "unit": "亿块",
      "period": "2025",
      "definition": "规模以上企业，累计产量",
      "evidence": ["s-0001"],
      "as_of": "2026-10-20",
      "frozen_at": "2026-10-21",
      "revision_note": null
    }
  ]
}
```

- fact 变更**只能新增版本**：旧条目 `revision_note` 写明被谁取代，新条目 `supersedes` 指回。
- 报告中的每个关键数字都必须能在 `facts.json` 找到，或标注为"单次引用，未冻结"。
- 复算（L0/L1 复核）就是拿 `facts.json` 的 `value` 重跑取数或换源核对。

## 6. 冲突登记 `conflicts.json`

```json
{
  "conflicts": [
    {
      "id": "x-0001",
      "topic": "2025 年中国集成电路产量增速",
      "positions": [
        { "evidence": "s-0001", "value": "12.3%", "basis": "国家统计局，可比口径" },
        { "evidence": "s-0014", "value": "9.8%", "basis": "行业协会，全口径" }
      ],
      "resolution": "explained | unresolved | preferred:s-0001",
      "rationale": "口径不同：统计局限上 vs 协会全口径；报告采用统计局口径并注明。",
      "owner": "worker-1"
    }
  ]
}
```

**禁止取平均、禁止静默选一个。** 未决冲突必须进报告"分歧与不确定性"章节。

## 7. 时效与失效

- 每个来源有 `retrieved_at`，每个 claim 有 `as_of`。
- 默认 **180 天**未复核即标记 `stale`（可在 `project.json` 用 `stale_days` 覆盖）。
- 交付前：`stale` 的 claim 要么复核，要么在局限章节声明。
- 引用二手来源时，必须尽量追到其上游一手源；追不到要在 `notes` 说明。

## 8. 溯源链

```text
报告数字 ─► f-0001 ─► s-0001 ─► meta.json ─► raw hash / locator ─► 取数参数
报告论断 ─► c-0001 ─► evidence[] ─► ...
```

任何一环断开，该结论不得以 high/medium 置信度出现。

## 9. `sa lint` 校验项

| 级别 | 检查 |
|---|---|
| error | meta 缺必填字段；claim 引用不存在的 source；claim 无证据却标 high/medium；fact 无 evidence；ID 重复；`project.json` 与 `03` 状态不一致；gate waiver 的 gate/字段非法；报告引用不存在的 fact/conflict；报告引用非 active 的 claim |
| warning | 来源超过 `stale_days`；E4 被直接用作证据；冲突 `unresolved` 但仍出现在报告引文中；孤儿来源（从未被引用）；报告引用的来源未被任何 claim/fact/conflict 使用；waiver 对应的门已标绿 |
| info | 覆盖矩阵缺口；未冻结的关键数字；gate waiver 条件性通过；高置信度 claim 未在报告中直接引用 |

错误必须清零才能过 G2/G3；警告需在 `03` 登记处置。

## 10. Gate waiver

某个阶段门只能"条件性通过"时，在 `project.json` 登记，不靠口头豁免：

```json
"gate_waivers": [
  {
    "gate": "G1",
    "reason": "市场数字仅有 E2 转引，未取得付费原始报告",
    "date": "2026-10-20",
    "approved_by": "manager",
    "scope": "q1 市场数据"
  }
]
```

- `gate` 必须是 G0–G3；`reason/date/approved_by` 必填。
- `_dev/03` 的门禁表必须把该门标为 🟡；标 🟢 仍留 waiver 会被 lint 警告。
- waiver 是**有范围的例外**，不是降级：缺口与替代方案仍须写入覆盖矩阵和报告局限。


## 新循环的应用

证据门槛和来源契约适用于所有研究。新项目在 research/cycle.json 中用 discussion/action/outcome 记录缺口及处置，用 answer 说明问题回答程度；旧 _dev/03 与 G0–G3 仅用于存量兼容。冻结的讨论和内部分析 artifact 不自动成为来源 evidence。
