## G0 · 立项与范围

**输入**：用户的口头需求 / 文档 / 数据。
**产出**：`project.json`、`brief/brief.md`、`_dev/01`、`_dev/02`（含子问题树）。

步骤：

1. **复述问题**：把用户需求写成 3–5 句的"研究问题陈述"，含决策场景（这份调研用来做什么决定）。
2. **划边界**：明确不做什么（地域、时间、主体、议题外延），写进 `out_of_scope`。
3. **定交付**：报告 / PPT / 数据表 / 口头简报；截止时间；密级与是否可公开。
4. **问全 A 层**：一次问完，不给施工期留悬念。常见清单：
   - 这份调研支持什么决策？
   - 结论要多细？给谁看？
   - 有没有必须覆盖的对象/必须回避的敏感面？
   - 时间范围与"截至日期"（as-of）？
   - 能用公开数据吗，还是要内部数据？
5. **拆子问题**：3–7 个，构成 `设计路线.md` 的树；每个子问题可独立回答、可独立验收。
6. **写验收标准**：G1/G2/G3 各自"完成"的具体样子。

**G0 门**：上面 6 步全部落纸，A 层无未答项。不满足不进 G1。

## G1 · 采集

**产出**：`search/` 下的来源信封、`queries.jsonl`、`analysis/coverage.md`。

### 1.1 先建覆盖矩阵

`analysis/coverage.md`：

```markdown
| 子问题 | E1 | E2 | E3 | 缺口 | 状态 |
|---|---|---|---|---|---|
| q1 市场规模 | s-0001 | s-0003 | s-0005 | 2026 年数据缺失 | 进行中 |
| q2 供应链 | — | s-0007 | — | 无一手源，需访谈/公告 | **缺口** |
```

矩阵是采集的**任务清单**，不是事后总结。每采到一个来源就回填。

### 1.2 检索原则

- **先结构化、后网页**：能用数据源（`kimi-datasource`）拿数就不用搜索；搜索用于补背景、找线索、验证口径。
- **每条检索都记日志**（`search/queries.jsonl`）：

```json
{"ts":"2026-10-20T09:10:00+08:00","tool":"datasource:china_nbs","query":"集成电路产量","params":{},"hits":3,"sources":["s-0001"]}
{"ts":"2026-10-20T09:20:00+08:00","tool":"websearch","query":"2025 中国集成电路 产量 统计公报","hits":10,"sources":["s-0003","s-0005"]}
```

  日志的意义：别人能复现你的检索路径，也能看出你**没搜什么**。
- **先一手后二手**：二手报告只用来定位一手数据；引用二手必须能说明其方法与口径。
- **反例优先**：看到与预期相反的数据，先入库，不要跳过。

### 1.3 入库

每个来源走同一个动作：建目录 → 写 `meta.json` → 存 `raw/`（可忽略）→ 写 `extracted.md` → 追加 `index.json`。

单条用 `sa source --title ...`；一次采到多条用 `sa source --batch sources.json`（字段见 `docs/06-数据源地图.md` §4）。批量文件里不写 id，由工具顺序分配。

`search/index.json`：

```json
{ "sources": [ { "id": "s-0001", "title": "...", "grade": "E1", "path": "s-0001-...", "added": "2026-10-20" } ] }
```

### G1 门

覆盖矩阵每个子问题至少 1 个 E1/E2；关键数字有 primary source；检索日志无断档；缺口显式登记（"没有"也是结论）。

## G2 · 分析收敛

**产出**：`claims.json`、`facts.json`、`conflicts.json`、`结论草案.md`。

### 2.1 提炼

- 一条 claim 一个可判真假的句子；一条 claim 至少一个证据。
- 先写"证据支持什么"，再写"我认为"；禁止反序。
- 数字类结论 → 提升为 fact，写清口径与期间。

### 2.2 反证轮（不可跳过）

由**红队**（非结论作者）执行，至少覆盖：

1. **反向检索**：搜"下降/质疑/例外/失败案例/相反观点"。
2. **口径攻击**：这个数字是不是换了统计口径？期间是否可比？
3. **来源攻击**：发布方有没有立场？数据是否被转载多次冒充独立来源？
4. **推理攻击**：相关当因果？样本偏差？幸存者偏差？
5. **时间攻击**：结论是否依赖过时数据？

产出写入 `_dev/04`：

```markdown
## 反证轮 · 2026-10-22 · 红队=advisor-2
- c-0003：找到 s-0014（协会口径 9.8%），已建冲突 x-0001，结论改为"统计局口径 12.3%"。
- c-0007：未找到反证；检索式见 queries.jsonl 第 41–48 条。
- c-0009：驳回——证据是同一篇稿件的两次转载，按单源降为 low。
```

### 2.3 收敛

- 每条 claim 定 `confidence`，写 `scope`、`as_of`。
- 未决冲突进 `conflicts.json`，`resolution=unresolved`。
- 结论草案按"子问题 → 结论 → 证据 → 置信度"组织，供报告直接取材。

### G2 门

`sa lint` 零错误；反证轮留痕；冲突有处置；高置信度 claim 全部可复算。

## G3 · 交付

步骤：

1. 按 `05-报告规范.md` 出报告；报告只引用 claim/fact id，不新造结论。
2. 交付前检查单逐项打勾（见下）。
3. 打版本快照 `deliverables/report/v1.0/`；需要 PPT 时按 `07-交付与PPT.md` 派生。
4. `project.json.status = delivered`；`03` 写终态；需要归档则整目录移入 `workspace/archive/`。

### 交付前检查单

- [ ] `sa lint` 零错误
- [ ] 报告每个数字都能追到 `f-*` 或 `s-*`
- [ ] 每个 high 置信度结论有 ≥2 独立来源
- [ ] 反证轮已执行，反方证据在报告中有位置
- [ ] 未决冲突与局限已如实写入
- [ ] `stale` 来源已复核或在局限中声明
- [ ] 关键数字抽 1–3 个独立复算
- [ ] 版本号、日期、as-of、密级齐全
- [ ] 结论没有超出 `scope` 的外推
- [ ] 交付物与 `03` 的验收标准逐条对齐
