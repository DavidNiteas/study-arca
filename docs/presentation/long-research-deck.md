# 已观察案例：长篇研究技术汇报

中文 | [English](../en/presentation/long-research-deck.md)

日期：2026-11-05。来源为一项长篇研究技术汇报的多轮迭代。案例只保留可迁移的设计关系，不复制项目研究数据、截图或交付文件。

## 状态与证据

- 状态：已观察案例。
- 版本记录：多轮版本产物与设计意图。
- 审查材料：逐版本自查与项目级发布记录。
- 反馈来源：首席研究员逐页反馈，版本推进至正式发布。
- 验证边界：目标软件实际渲染、逐页看图、机器溢出检查、报告校验与发布哈希已完成；没有独立设计复核，不把首席研究员接受解释为科学结论独立验证。

## 读者问题与信息关系

读者既需要理解研究故事，也需要判断多个模型、软件系统和证据之间的关系。主要信息关系包括：

- 研究路线与系统架构；
- 已知对象、候选对象与未知对象之间的证据差异；
- 批量运行、专家审核与模型反馈闭环；
- 软件业务流、状态机和对象生命周期；
- 原始结果与软件实例；
- 研究进展、当前缺口和后续安排。

## 原设计与失败现象

初版虽然完成了完整结构与技术图，但仍出现几类重复问题：

1. 机器检查已显示文字溢出为 0，仍出现图例贴近节点、说明压框和视觉中心不清。
2. 部分页面先铺卡片，再往卡片里填内容，无法直接看出过程、层级或证据差异。
3. 标题承担叙事口号，副标题弱化为浅色说明，读者无法快速得到页面结论。
4. 技术路线、系统架构和业务流混在同一视觉任务中，组件清单替代了关系。
5. 页面有大量未利用空间，同时主对象、关键句或证据图偏小。
6. 用临时图形、免责声明和推导数字填补证据不足，破坏了研究表达的边界。
7. 后续插入分节页、子 session、目录和软件截图后，页码与页序关系成为新的维护风险。

## 有效设计与选择理由

### 1. Session 导航骨架

最终采用：

```text
封面 → 目录 → 主 session → 子 session → 内容页 → 进展总结 → 结束致谢
```

目录同时显示主 session 和必要的子 session；页码从实际页面结构计算。长篇内容由此获得稳定定位，而不是依靠连续卡片堆叠维持节奏。

### 2. 一页一个认知任务

同一页只突出一个问题：路线页解释方法如何汇合，架构页解释组件职责，业务流页解释输入和输出，状态机页解释恢复与迁移，评估页只展示评估结果。

### 3. 关系先于容器

将网状、循环、分层、状态、矩阵、流程和空间关系分别转成原生矢量图。相同关系复用视觉语法，不同问题拆页，不把所有内容处理成等大卡片。

### 4. 分层证据地图

未知对象密集的页面采用“已知锚点 → 未知空间 → 验证出口”的三段结构，并在底部保留对象状态推进链。空间位置承担认知边界，而不是任意聚类。

### 5. 原始证据优先

- 评估页直接使用用户提供的原始结果图，按其原始比例横向排列。
- 定量评估页只保留来自原始表的指标图和必要分组。
- 软件实例使用真实界面截图，一图一页，不增加重复说明。

### 6. 对齐优先，容器后置

封面最终通过边界、基线、同高区域和同宽横条完成组织。可见边框与背景底色并非必要；对齐本身足以建立分组。标题与左侧对象共享内容边界，贯穿竖线建立纵向轴。

### 7. 空间需要强化主对象

当页面下部失衡时，先放大下方节点、延长连接线、放大关键句或移动单图，而不是添加装饰。页面拥挤时，优先拆页和删除低价值说明，而不是持续缩小字号。

### 8. 页面文字角色化

- 标题命名对象、模块、判断或清晰问题。
- 页面主张在需要时给出独立结论；单图、真实截图和原始结果页可以省略主张句。
- 标注只服务对象、关系、单位和状态。
- 收口句只压缩本页判断，不重复标题或引入新论证。
- 页码、章节名与页脚只负责导航。

## 迭代阶段

| 阶段 | 主要变化 |
|---|---|
| 早期结构 | 修正文字溢出、说明压框、图例距离等机械问题 |
| 视觉语言 | 建立画布、字体层级、封面概念图和内容路径 |
| 全篇系统化 | 统一网格、页脚、标题安全区和学术措辞 |
| 关系图型 | 发展三联图、循环、流程、矩阵和证据对照 |
| 导航结构 | 建立主分节、子专题、自动目录和发布边界 |
| 证据强化 | 使用真实结构、原始结果、真实软件截图和业务流 |
| 发布精修 | 处理对齐、空间利用、去边框、去底色和目录页序 |
| 冻结发布 | 固定版本、生成发布目录和自包含校验 |

## 可迁移结论

- 长篇研究 deck 是“叙事结构 + 页面语义 + 关系图型 + 版面力学 + 发布控制”的组合问题。
- 内容页的标题、主张、证据标签、收口句和导航文字应有不同职责。
- 大类研究内容可用主 session 与子 session 组织，但数量与层级由内容决定，不设固定配额。
- 对齐和留白属于结构工具；边框、底色和卡片是后置选择。
- 原始结果图、真实截图与可编辑原生图各有位置，不能用装饰图替代证据。
- 发布前必须检查目录页码、标题安全区、图片比例、实际渲染、外部引用和文件哈希。

## 不可直接外推的部分

- 固定画布尺寸、具体字号、颜色、列数、页面比例和封面构图。
- 项目使用的等级量表及具体完成层级。
- 子 session 数量、软件模块数量、项目特有插画或特定科学对象。
- 本案例的自查结论不等于独立复核，也不证明其他软件渲染结果一致。
