# 11 · PPT Design Method

[中文](../11-PPT设计方法与模式.md) | English

## Start with relationships

Identify the main relationship before choosing a visual form: comparison, composition, process, hierarchy, state, matrix, network, spatial relation, or evidence difference. Use a table when exact lookup is clearer.

## Long-deck structure

```text
Cover → Contents → Main sessions → Necessary sub-sessions
→ Content → Summary → Closing
```

Generate page references from actual slide order. Do not force a sub-session into every section.

## Text roles

- title: object, component, decision, or concise claim;
- page claim: one independent insight, optional on image-heavy pages;
- evidence labels: objects, units, states, relationships;
- closing statement: compression only, no new argument;
- navigation: page and section metadata only.

## Layout

- Identify one visual center and one reading path.
- Use alignment and spacing before containers.
- If space is empty, enlarge the primary object; if crowded, split or remove.
- Preserve image aspect ratios.
- Use color and line style consistently.
- Do not imply similarity, causality, or priority through decoration.

## Review loop

```text
Source → design intent → DeckPlan + RenderLayout → native PPTX
→ target renderer → inspect images → classify issue
→ revise source / intent / layout / renderer → rebuild
```

Classify issues as source, semantic, layout, rendering, or release. Read the images; a zero-overflow report is not visual acceptance.
