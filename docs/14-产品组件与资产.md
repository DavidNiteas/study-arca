# 14 · 产品组件与资产

本文件定义 Study Arca 产品仓中各目录的职责、权威关系和引用方式。核心目标是避免把“代理方法”“规范知识”“文件骨架”和“当前研究事实”混为一谈。

## 1. 组件总览

| 组件 | 回答的问题 | 主要使用者 | 是否会被 `sa new` 复制 |
|---|---|---|---|
| `docs/` | 为什么这样做，正确边界是什么？ | 人、代理、复核者 | 否 |
| `.agents/skills/` | 遇到某类任务时，代理应按什么流程执行？ | 代理执行环境 | 否 |
| `templates/` | 新建项目、报告或图形记录时，初始文件应该长什么样？ | `sa new`、研究人员 | `templates/project/` 会 |
| `src/`、`scripts/` | 如何通过代码验证、记录、渲染和执行？ | CLI、项目工具 | 否 |
| `workspace/` | 当前正在做的真实研究是什么？ | 研究人员 | 否 |
| `RELEASE.json`、`VERSION` | 当前产品版本和文件完整性如何确认？ | 发布与复核流程 | 否 |

目录关系：

```text
代理执行入口（.agents/skills）
        ↓ 读取
规范与权威定义（docs）
        ↓ 调用
实现与公共接口（src / scripts）
        ↓ 使用
文件骨架（templates）
        ↓ 生成
独立研究项目（work-root/nodes/*）
```

## 2. `.agents/skills`：代理执行层

`.agents/skills/` 是代理工具按约定发现和执行技能的目录。当前技能：

- [research-cycle](../.agents/skills/research-cycle/SKILL.md)：研究循环、补证、分析、讨论和呈现的任务路由。
- [presentation-design](../.agents/skills/presentation-design/SKILL.md)：研究呈现设计、实际渲染、读图与返修。
- [workspace-system](../.agents/skills/workspace-system/SKILL.md)：工作区类型、本地工单、引用物化和方言边界。

职责边界：

- 定义任务入口、顺序、质量检查和交接要求。
- 指向 `docs/` 中的规范真源，不复制完整 schema。
- 按任务引用 `templates/` 中的记录格式。
- 不保存研究事实、来源、claim、当前项目状态或交付版本。
- 不被复制到新建研究项目中。

技能可以读取产品和项目文件，但不得把技能文本本身当作证据来源。

## 3. `templates`：生成骨架层

`templates/` 是版本化的空白结构，不保存当前项目的真实答案。

| 目录 | 用途 | 生产者与消费者 |
|---|---|---|
| [`templates/project/`](../templates/project/) | 新调研项目的目录、元数据、台账、报告工作区和发布/打包骨架 | `sa new` 复制并替换 `{{ID}}`、`{{TITLE}}`、`{{DATE}}` 等占位符 |
| [`templates/report/`](../templates/report/) | Markdown 报告与 `sa.report-plan/1` 起始结构 | 新项目报告、`sa report init` 或人工写作 |
| [`templates/ppt/`](../templates/ppt/) | PPT 大纲、设计意图和设计案例记录 | `presentation-design` 技能与研究人员 |
| [`templates/research/`](../templates/research/) | 关键论文分析和研究循环记录样例 | 分析任务与 `research-cycle` 技能 |
| [`templates/output/`](../templates/output/) | 输出请求、DocumentPlan、ExperiencePlan、DeckPlan、布局和登记样例 | 三种独立输出流程 |
| [`templates/synthesis/`](../templates/synthesis/) | 复盘/设计轮次、问题、回答、修正、设计决定与对齐记录样例 | Synthesis 工作区复盘与设计循环 |
| [`templates/dialect/`](../templates/dialect/) | 首席研究员级方言起始清单 | 首席研究员本机初始化，不进入发布历史 |
| [`templates/program/`](../templates/program/) | Program superproject 的最小清单和操作说明 | Program 初始化与人工参考 |

职责边界：

- 只提供结构、字段说明和占位符。
- 不保存真实来源、数字、结论、批准、审查意见或交付状态。
- `templates/project/_dev/` 是**存量研究项目内部的兼容治理模板**，不是 Study Arca 开发仓的 `_dev/`。
- 模板变化影响所有新项目的起点，应由产品或开发工单明确记录，并同步检查 `sa new` 和相关测试。

## 4. `docs`：规范权威层

`docs/` 定义 Study Arca 的业务与交付规则，是技能和模板共同引用的权威来源。

- 研究循环、接收、状态和字段解释以 [09](09-专业调研循环.md) 为准。
- 代理接手顺序以 [10](10-代理工作协议.md) 为准。
- PPT 设计与视觉反馈以 [11](11-PPT设计方法与模式.md) 为准。
- 呈现能力边界以 [12](12-系统定位与能力管理.md) 为准。
- 研究论证质量以 [13](13-研究分析与论证.md) 为准。
- 总结型工作区的复盘、设计、对齐、快照和适配输出以 [16](16-复盘对齐与适配输出.md) 为准。
- 首席研究员、主代理双身份、研究顾问委员会和研究专员的权责以 [17](17-研究协作角色.md) 为准。
- 正式报告的内容映射、叙事编排及 HTML/DOCX/PPT 输出以 [18](18-报告编排与输出.md) 为准。

当 skill 与 docs 发生冲突时，以 docs 为准；skill 应改为薄路由。

## 5. 组合使用流程

1. 代理从 `.agents/skills/` 找到任务入口。
2. 技能要求代理读取相应 `docs/` 规范。
3. 需要新建项目时，代理调用 `scripts/sa.py new`。
4. CLI 从 `templates/project/` 生成独立项目。
5. 项目和实际研究数据进入 `work-root/nodes/*`，后续修改只作用于该项目。
6. 报告、PPT 和研究记录按 `docs/` 规则组织，必要时引用 `templates/` 中的记录格式。
7. 发布前检查 `RELEASE.json`、代码测试和产品历史边界。

## 6. 修改责任

| 修改内容 | 应修改的位置 | 必须同步检查 |
|---|---|---|
| 代理执行顺序、任务路由、交接要求 | `.agents/skills/<name>/SKILL.md` | 对应 `docs/` 权威章节 |
| 研究原则、字段含义、证据门槛、质量边界 | `docs/` | 技能引用、模板字段、CLI 校验 |
| 新项目目录或默认文件 | `templates/project/` | `src/sa/project.py`、`tests/`、`docs/02` |
| 报告或 PPT 骨架 | `templates/report/`、`templates/ppt/` | `docs/05`、`docs/07`、`docs/11` |
| 真实研究问题、证据、状态和交付 | `work-root/nodes/*` 项目仓 | 项目 `research/cycle.json` 与交付记录 |

## 7. 禁止事项

- 不把 `.agents/skills` 改造成研究项目模板库。
- 不把 `templates/` 中的占位内容当作真实研究证据。
- 不在 skill 中复制整套 docs；只保留入口和最小执行要求。
- 不把当前项目数据反写进 `templates/`。
- 不把 `work-root/nodes/*` 的数据提交进产品 Git 历史。
- 不把研究项目内部的 `_dev/` 模板与开发仓治理记录混同。

## 8. 快速定位

- 想知道“代理该怎么做”：看 `.agents/skills/`。
- 想知道“为什么规则如此”：看 `docs/`。
- 想知道“新项目从什么开始”：看 `templates/`。
- 想知道“代码怎么执行”：看 `src/` 与 `scripts/`。
- 想知道“当前研究得出什么”：看 `work-root/nodes/*`。
