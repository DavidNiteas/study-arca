## 2. 选源纪律

1. 一次简单查询只选**一个**源，成功覆盖即停，不为"交叉验证"顺手多查（真正的交叉验证在 G1 覆盖矩阵里做）。
2. 结构化数据优先于网页；网页优先于二手报告。
3. 数据源报错先读报错文本，**不硬试第二次**；参数 schema 自相矛盾属后端 bug，记录并上报。

## 3. 已知坑

| 坑 | 规避 |
|---|---|
| 股票代码凭记忆猜 | 调用前用 websearch 核对 `600519.SH` 这类后缀 |
| 企业简称被拒 | 先走 tianyancha 公司搜索拿全称 |
| 漏 `file_path` | 绝大多数 API 把 CSV 写到本地，必须传 |
| Wind 字段名 | 先 `wind_search_fields` 查原生字段，别猜 PE/PB |
| 混合 A+港股返回拆文件 | 原 `file_path` 可能不存在，看 `_a.csv` / `_hk.csv` |
| yahoo 外汇历史只有约 2 年 | 长期汇率用 `imf` |
| 二手报告的口径 | 入库时写进 `notes`，别当一手用 |
| 新闻稿互相转载 | 视为同一来源，不构成"两个独立来源" |

## 4. 来源入库模板

用数据源取数后，即刻建信封（不要等）：

```bash
python scripts/sa.py source <project-dir> \
  --title "..." --tool datasource:china_nbs \
  --locator "<url 或参数>" --publisher "国家统计局" \
  --grade E1 --query "集成电路产量" --slug ic-output-2025
```

`raw/` 放 CSV 原件；`extracted.md` 写表名、字段、口径、关键摘录。

批量入库（一次采到多条时用）：

```bash
python scripts/sa.py source <project-dir> --batch sources.json
```

`sources.json` 为数组，字段与单条参数一致，额外支持 `extracted` 直接写入正文：

```json
[
  {
    "title": "国家统计局 2025 统计公报",
    "tool": "datasource:china_nbs",
    "locator": "https://data.stats.gov.cn/",
    "publisher": "国家统计局",
    "grade": "E1",
    "type": "gov",
    "query": "集成电路产量",
    "slug": "ic-output-2025",
    "notes": "月度数据按年汇总",
    "extracted": "# s-0001 ...\n\n## 关键摘录\n\n> ..."
  }
]
```

ID 仍由工具顺序分配，输入里不要写 id。
