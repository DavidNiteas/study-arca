# 17 · 研究协作角色

> 本文定义 Study Arca 研究工作区中的协作角色、授权边界、顾问委员会和研究专员机制。它描述产品内的研究协作，不定义开发仓的工程治理角色。

## 1. 角色边界

Study Arca 的目标使用者是研究工作的主理人，产品内统一称为**首席研究员**。

```text
首席研究员
├── 主代理
│   ├── 研究助理
│   └── 助理研究员
├── 研究顾问委员会
│   └── 研究顾问 × 2 或以上
└── 研究专员
```

工程开发中的经理、干事和顾问不进入研究工作区。开发经理只负责 Study Arca 本身的设计、工单和施工。

## 2. 稳定标识与显示名称

角色名称属于产品展示层，记录使用稳定标识：

| 标识 | 显示名称 | 性质 |
|---|---|---|
| `principal` | 首席研究员 | 人和最终决定者 |
| `research_assistant` | 研究助理 | 主代理的服务型身份 |
| `assistant_researcher` | 助理研究员 | 主代理的研究设计身份 |
| `research_advisor` | 研究顾问 | 只读顾问实例 |
| `advisory_panel` | 研究顾问委员会 | 针对一个问题组织的顾问会话 |
| `research_specialist` | 研究专员 | 边界明确的一站式研究任务执行者 |

首席研究员名称可以通过工作区方言调整显示名称，但 `principal` 是稳定的机器标识。

## 3. 首席研究员

首席研究员负责：

- 研究目标、问题、范围和优先级；
- 资料访问与外部工具授权；
- 设计方案的接受、否决、延期和替代；
- 研究发现和科学判断；
- 对外披露范围与交付取舍；
- 决定继续、下钻、跳出或暂挂。

主代理、研究顾问和研究专员都不能代替首席研究员作出上述决定。

## 4. 主代理双身份

同一个主代理承担两种工作身份，不拆成两个长期并行代理。

| 身份 | 主要职责 | 禁止 |
|---|---|---|
| 研究助理 | 接住口述、复述理解、整理材料、发现缺口、维护记录、提示下一步 | 擅自扩大范围；把推断冒充事实；自行发起范围外调研 |
| 助理研究员 | 分析、建立概念模型、提出方案、比较备选、批评矛盾、形成研究设计 | 代替首席研究员接受设计；把代理提案标成已确认结论 |

### 4.1 切换规则

- 首席研究员提供经历、资料、状态和个人判断时，默认进入研究助理身份；
- 首席研究员明确提出分析、设计、比较、规划或研究问题拆解时，进入助理研究员身份；
- 同一轮允许混合，但每项提案、决定和事实必须保留来源；
- 对齐时由助理研究员完整讲解叙事，由研究助理负责结构化记录；
- 冻结时，主代理只把首席研究员接受的设计写入 design baseline。

### 4.2 输出标记

代理提案应明确标记为“提案”或“建议”。只有在首席研究员确认后，才能进入“已接受设计”。

## 5. 研究顾问

研究顾问是针对明确问题提供独立分析的只读角色。它可以：

- 查阅授权范围内的材料、代码、数据和外部来源；
- 核查证据、提出替代解释和反例；
- 评估设计、方法和风险；
- 提出后续调查方向；
- 输出结构化顾问备忘录。

研究顾问不得：

- 修改工作模型、ledger、快照或其他工作区文件；
- 自行扩大材料访问范围或执行外部写操作；
- 代表主代理与首席研究员对齐；
- 宣布方案已接受；
- 把多数意见当作证据。

## 6. 研究顾问委员会

研究顾问委员会不是常驻人格，也不是一个拥有统一意志的“超级顾问”。它是一次针对具体问题和授权的顾问会话。

### 6.1 两种委员会模式

| 模式 | 目的 | 组织要求 |
|---|---|---|
| `replicate` | 观察同一问题的观点波动、遗漏和稳定性 | 相同材料、相同问题、不同独立实例 |
| `heterogeneous` | 覆盖不同视角和探索方向 | 不同模型、不同方法视角或不同审查任务 |

同题重复产生的是变异观察，不是独立证据。不得把多个实例的一致意见自动写成高证据等级。

### 6.2 独立性

- 每个研究顾问先独立回答，不能先看其他人的结论；
- 每个顾问明确自己的问题、范围、材料和方法；
- 主代理负责综合，不以简单多数票替代证据；
- 一致结论、分歧、少数观点、未覆盖问题和不可支持主张必须分别保留。

### 6.3 委员会会话

委员会会话至少记录：

```text
panel_id
question
mandate
mode
members
shared_inputs
independent_memos
synthesis
unresolved_disagreements
created_by
status
```

顾问备忘录至少包含：

- 结论；
- 支持依据；
- 反证、反例和不确定性；
- 关键假设；
- 备选解释；
- 建议的调查方向；
- 使用的材料与来源。

不需要把完整探索过程塞回主代理上下文。主代理消费结构化备忘录和来源指针。

### 6.4 不适用场景

普通问询、单点事实确认、小范围整理或无显著不确定性的任务，不默认启动委员会。

## 7. 研究专员

研究专员执行边界明确、可以独立交付的一站式任务，例如：

- 整理材料和证据；
- 提取、归一化和比对信息；
- 审查对齐记录或研究产物；
- 运行只读或授权范围内的数据检查；
- 起草结构化表、备忘录或局部设计；
- 复核另一个研究专员的产物。

研究专员不得：

- 决定研究目标、范围或设计接受；
- 与首席研究员完成最终对齐；
- 自行扩大任务范围；
- 对同一产物既生产又充当独立审查者。

### 7.1 任务包

派发研究专员时至少说明：

```text
任务目标
输入材料
允许范围
允许的写入位置
产出格式
禁止事项
完成标准
```

### 7.2 结果包

结果至少包含：

```text
实际执行范围
采用方法
产出
关键证据
限制与不确定性
未解决问题
建议后续动作
```

研究专员可以完成工作，但不拥有研究判断的最终权威。

## 8. 授权与上下文

采用“按轮授权、轮内自主”：

1. 首席研究员批准一轮的目标和边界后，助理研究员可以在范围内启动研究顾问或研究专员；
2. 研究助理身份下不自行发起范围外调研；
3. 扩大研究范围、启动明显高成本任务、执行外部写操作、改变已接受设计时，必须重新请求首席研究员；
4. 子代理只接收完成当前问题所需的上下文，避免把整个主对话复制给每个实例；
5. 顾问和专员的结果进入主代理前应压缩为结构化结论、证据和未决项。

## 9. 来源与决定链

未来机器记录应能区分：

```text
actor_role
agent_stance
panel_id
advisor_id
specialist_task_id
proposal_origin
decision_owner
```

至少保留以下关系：

```text
材料 / 首席研究员陈述
  → 研究助理或专员整理
  → 顾问意见或助理研究员提案
  → 主代理综合
  → 首席研究员决定
  → design baseline / knowledge baseline
```

顾问意见不会因为被主代理引用就自动成为事实；研究专员产出也不会因为生成了文件就自动成为已确认内容。

## 10. 与工程治理的关系

Study Arca 借用工程治理中的两项机制：

- 顾问只读、可并行、只提供观点；
- 专员接受一个完整任务并在边界内机动执行。

但不移植经理、干事和开发阶段门。研究工作的目标、范围、判断和最终决定仍归首席研究员；主代理的两种身份负责服务、分析、设计和记录。

## 11. 当前实现边界

D6 已在 `sa.synthesis/1` 中支持：

- `advisory_panel` 会话、至少两位研究顾问、独立意见与综合；
- `specialist_task` 任务范围、执行角色、产出、限制和未决项；
- `design_proposal`、`design_decision` 和 `design_artifact` 的角色来源；
- 设计接受、否决、延期、替代和历史设计保留。

具体模型的启动、并发、超时、成本和上下文隔离由宿主执行环境提供。规范保证这些协作结果如何被记录和校验，不保证任意环境都具备同时启动多个模型实例的能力。
