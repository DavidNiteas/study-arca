# 00 · 使用指南

中文 | [English](en/00-getting-started.md)

本文件面向第一次使用 Study Arca 的人。它说明系统由什么组成、任务从哪里开始、结果如何流转，以及需要查哪份权威规范。

## 1. 一张图理解系统

```text
Program（组织多个工作区）
  └─ Workspace（一个独立研究对象或总结对象）
       ├─ brief/          首席研究员提供的信息与材料
       ├─ work-orders/    工作区自己的任务
       ├─ references/     其他工作区事实的物化副本
       ├─ synthesis/      复盘、设计、对齐与冻结范围
       ├─ report/         报告计划、布局、成品与预览
       ├─ outputs/        正式输出与审查登记
       ├─ deliverables/   内部冻结快照
       ├─ archive/        已退役开发历史
       └─ publish/        对外发布成品
```

Program 只管理成员关系和版本 pin，不承载下层事实。Workspace 才是研究对象、证据、工单、结论和输出的归属单元。

## 2. 两种工作区

| 目的 | 工作区类型 | 主要流程 | 权威说明 |
|---|---|---|---|
| 研究外部问题、收集来源、形成结论 | `research` | 立项 → 调研 → 分析 → 讨论 → 呈现 | [09](09-专业调研循环.md) |
| 整理本人工作、复盘、设计或适配输出 | `synthesis` | 复盘 ⇄ 设计 → 对齐 → 冻结 → 输出 | [16](16-复盘对齐与适配输出.md) |

工作区类型必须写入 `project.json`，不能根据目录名猜测。完整布局、工单、引用和方言规则见 [15](15-工作区身份工单与方言.md)。

## 3. 快速开始

### 新建研究型工作区

```powershell
python scripts/sa.py program init <program-path> --id prog-main --title "我的研究 Program"
python scripts/sa.py new market-scan --title "市场扫描" --type research --program <program-path>
python scripts/sa.py cycle init <program-path>/nodes/p-*-market-scan
python scripts/sa.py lint <program-path>/nodes/p-*-market-scan
```

### 新建总结/设计型工作区

```powershell
python scripts/sa.py new project-review --title "阶段复盘" --type synthesis --program <program-path>
python scripts/sa.py input add <program-path>/nodes/p-*-project-review --file <material>
python scripts/sa.py synthesis init <program-path>/nodes/p-*-project-review
python scripts/sa.py synthesis validate <program-path>/nodes/p-*-project-review
```

首席研究员可以把未登记材料放入 `brief/inbox/`。主代理先盘点并与首席研究员确认，再用 `sa input add` 复制并登记到 `brief/provided/`。未登记材料不进入事实模型。

Program 根按 `--program`、`SA_PROGRAM_ROOT`、最近祖先 `program.json` 的顺序发现。旧产品内 `work-root/` 和 `workspace/` 仅作迁移兼容；产品仓不再包含默认数据根。

`--root` 是底层逃生口：它只选择一个工作区容器，不会把新工作区登记为 Program 子模块。常规使用应优先建立 Program。

## 4. 正式报告与 PPT

正式多受众输出使用独立报告链：

```text
冻结来源 → ReportPlan → ContentMap / NarrativePlan
→ ReportDocument → DOCX / HTML / PPTX → output review
```

基础命令：

```powershell
python scripts/sa.py report init <workspace> --id rpt-0001 --title "报告标题"
python scripts/sa.py report validate <workspace> --id rpt-0001
python scripts/sa.py report document <workspace> --id rpt-0001
python scripts/sa.py report build <workspace> --id rpt-0001 --format pptx
python scripts/sa.py report register <workspace> --id rpt-0001 --format pptx --preview <preview-dir>
python scripts/sa.py output lint <workspace>
```

PPT 的原生构建和预览：

```powershell
python scripts/sa.py deck validate <workspace> --plan <plan.json> --layout <layout.json>
python scripts/sa.py deck build <workspace> --plan <plan.json> --layout <layout.json> --output <deck.pptx>
python scripts/sa.py deck preview <workspace> --pptx <deck.pptx> --out-dir <preview-dir>
```

设计方法见 [11](11-PPT设计方法与模式.md)，报告编排见 [18](18-报告编排与输出.md)，发布与视觉验收见 [07](07-交付与PPT.md)。

## 5. 发布、打包与历史归档

三类不同产物不能混用：

| 目录/命令 | 用途 |
|---|---|
| `publish/vX.Y/` | 不可变正式发布目录 |
| `publish/release/` | 最新发布版本的稳定副本 |
| `sa pack` → `publish/packed/` | 首席研究员明确要求时的对外压缩包 |
| `sa report archive` → `archive/reports/` | 清理被新版本取代的开发历史 |

```powershell
# 发布包：只有明确要求才执行
python scripts/sa.py pack <workspace> --version v1.0

# 开发历史归档：默认只看计划
python scripts/sa.py report archive <workspace> --id rpt-0001 --before v1.0
python scripts/sa.py report archive <workspace> --id rpt-0001 --before v1.0 --apply
python scripts/sa.py report archive <workspace> --id rpt-0001 --before v1.0 --verify
```

归档 `.zip` 和 Git 历史备份 `.bundle` 默认不进入 Git；manifest 与重写记录保留审计信息。Git 历史重写会改变提交哈希，必须由首席研究员明确授权并先做可验证备份。完整规则见 [07](07-交付与PPT.md)。

## 6. 角色与协作

- **首席研究员**：目标、范围、判断和最终接受权的拥有者。
- **主代理**：在复盘时作为研究助理，在设计时作为助理研究员；负责组织、整理、追问和交付。
- **研究顾问 / 顾问委员会**：提供解释、方案和分歧，不替首席研究员拍板。
- **研究专员**：在明确任务包内执行整理或审查，不拥有最终设计接受权。

完整边界见 [17](17-研究协作角色.md)。

## 7. 数据放在哪里

- 首席研究员原始输入：`brief/provided/`
- 外部来源和原始响应：`search/`（research 工作区）
- 当前合成过程与认知记录：`synthesis/`
- 可重建的报告计划与布局：`report/`
- 正式输出和审查：`outputs/registry.json`
- 冻结交付：`deliverables/`
- 正式发布：`publish/`
- 历史开发归档：`archive/`

大数据、原始实验文件和公开数据集可以外部引用；只要工作区结论直接依赖其内容，就应在 `references/` 或材料清单中保存可校验的身份信息与必要副本。见 [15](15-工作区身份工单与方言.md)。

## 9. 文档层级

1. **使用指南**：帮助你选路径，不定义业务事实。
2. **权威规范**：定义可执行规则和字段边界。
3. **代理技能**：规定某类任务的执行顺序，不复制规范真源。
4. **模板**：只提供骨架与占位符。
5. **项目工作区**：保存真实来源、分析、状态和交付。

发生冲突时，以权威规范为准；技能和模板应随之修正。

## 10. 完成一轮工作的判断

- 原始输入和推断没有混写；
- 重要结论有来源或明确标为未知；
- 设计、对齐和冻结范围可追溯；
- 正式输出绑定冻结内容；
- 实际渲染已检查，审查状态已登记；
- 对外发布和历史清理均经过首席研究员明确授权。
