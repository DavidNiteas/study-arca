# 研究呈现设计

先从当前目录或父目录找到含 scripts/sa.py 与 docs/11-PPT设计方法与模式.md 的宿主仓；找不到则说明缺少规范，不猜其他工具的能力。此技能随仓库使用，不依赖某个模型供应商。

1. 读 docs/10-代理工作协议.md 接手当前约定、材料、反馈与任务；读 docs/11-PPT设计方法与模式.md 选择表达方法。交付细节按 docs/07-交付与PPT.md，能力边界按 docs/12-系统定位与能力管理.md。
2. 先确认内容来源、受众与核心表达，再判断信息关系。默认原创画布；用户明确指定模板时保留其选择。不要把所有页面变成卡片，也不要为了变化删除必要表格。
3. 参照 templates/ppt/design-intent.md 记录轻量设计意图；按任务读 docs/presentation/README.md 中相关案例。案例供解释选择，不复制固定坐标或直接充当业务证据。
4. 检查实际渲染与读图能力；编辑布局 LR，用目标软件渲染，实际看图并按页码/元素 ID 返修。检查语义、可读性和全篇节奏；最终读图才登记通过，self 不冒充 independent。内容问题回到分析。
5. 按 docs/09-专业调研循环.md 冻结意图、内容、布局、输出、预览与审查记录，使用既有材料引用登记。记录尚未解决的限制；执行 cycle lint 和项目 lint。
6. 有实际可迁移经验时，用 templates/ppt/design-case.md 先在项目内保存观察；通用规范/技能修改走框架工单，不自动公开项目资料。不为每个成功页面制造新的硬规则。

工具缺失或看图失败时交接已完成部分和阻塞点，不宣称完成视觉验收。记录当前输出，不复用旧版通过结论。
