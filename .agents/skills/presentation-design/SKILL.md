# 研究呈现设计

先从当前目录或父目录找到含 scripts/sa.py 与 docs/11-PPT设计方法与模式.md 的宿主仓；找不到则说明缺少规范，不猜其他工具的能力。此技能随仓库使用，不依赖某个模型供应商。

组件关系见[产品组件与资产](../../../docs/14-产品组件与资产.md)：本 skill 定义呈现执行流程；规范真源在 `docs/`，大纲/意图/案例骨架在 `templates/ppt/`，最终版面与审查材料绑定项目。

1. 读[代理工作协议](../../../docs/10-代理工作协议.md)接手当前约定、材料、反馈与任务；读[PPT 设计方法与模式](../../../docs/11-PPT设计方法与模式.md)选择表达方法。交付细节按[交付与 PPT](../../../docs/07-交付与PPT.md)，能力边界按[系统定位与能力管理](../../../docs/12-系统定位与能力管理.md)。
2. 先确认内容来源、受众与核心表达，再判断信息关系。长篇内容先建立主 session、必要的子 session 和实际页序；每页只承担一个主要认知任务。区分标题、页面主张、证据标签、收口句和导航文字：主张句只在实际提供独立结论时出现，单图或原始结果页可省略。默认原创画布；用户明确指定模板时保留其选择。不要把所有页面变成卡片，也不要为了变化删除必要表格。
3. 参照[design-intent.md](../../../templates/ppt/design-intent.md)记录轻量设计意图；按任务读[呈现案例索引](../../../docs/presentation/README.md)。案例供解释选择，不复制固定坐标或直接充当业务证据。
4. PPT 的通用路径是 `sa deck convert|validate|build`。需要真实预览时运行 `sa deck preview`，检查逐页 PNG、PDF、文字溢出、联系表和全篇总览；再实际看图并按页码/元素 ID 返修。机器测量不能替代读图，self 不冒充 independent。先判断问题属于内容/来源、语义编码、布局、渲染还是发布，再回到对应层修复。拥挤时优先删减或拆页；空间失衡时优先放大主对象、延长关系和调整对齐，不用装饰填满空白。边框、卡片和底色是后置选择，对齐本身足以分组时不要增加容器。
5. 按[专业调研循环](../../../docs/09-专业调研循环.md)冻结正式输出所需的快照或 synthesis 基线、请求、计划、布局、成品和预览，再追加 output；审查作为独立 review 事件，携带冻结的 preview artifact。失败、返修和复验分别保留。记录尚未解决的限制；按工作区身份执行 `sa synthesis validate`（兼容旧 research 工作区时执行 `cycle lint`），再执行项目 lint。
6. 发布前确认目录、章节号与页码来自最终页面结构，图片保持比例，原始图表和截图可追溯，标题不侵入装饰或页码安全区，PPTX 无外部资源依赖。不能由来源支撑的数字和结论不得通过图形、面积或位置暗示。
7. 有实际可迁移经验时，用[design-case.md](../../../templates/ppt/design-case.md)先在项目内保存观察；通用规范/技能修改走框架工单，不自动公开项目资料。单个成功样例先标为“已观察案例”，不为每个成功页面制造新的硬规则。
8. 案例或规范进入产品仓前必须去项目化：检查项目名、业务对象、版本号/页数统计、本地路径、人员信息、截图和交付物，并同时检查当前树与 Git 历史。发现本地历史泄露时先停止推送，按 `docs/07` 的 Git 历史维护流程清理；不要把敏感词加入产品代码作为检测常量。

工具缺失或看图失败时交接已完成部分和阻塞点，不宣称完成视觉验收。记录当前输出，不复用旧版通过结论。
